# 投资项目政策归集：判定规则与官网接入

检查基线：`improve/policy-ingestion`，提交 `4cce8c77276b7e3b5f4c548492aad7f4aaf112f9`。本次修改的业务依据是任务书四类定义；争议项没有冒充指导员确认，也没有改动原始56条标签。

## 1. 两个核心问题如何验收

- 判断规则：从原文找到“适用对象＋实质措施”，说明为什么属于投资项目政策，每个分类分别有证据；判不下去时说明具体原因。
- 官网接入：能从确定的官方政策栏目持续发现文件，取得正文和附件，保存来源与元数据，去重入库；知道采了哪些页、漏在哪个环节、能否补采。

“有投资/项目关键词”不能证明业务相关；“首页返回200”不能证明已接入；“两个页面成功”不能证明全省或历史数据已采全。

## 2. 可执行判定顺序

| 规则 | 判定问题 | 依据及处理 |
|---|---|---|
| R1 来源 | 来自配置确认的政府官网政策栏目吗？ | 任务书明确要求。按官网域名、栏目、详情路径控制。栏目目录见 sources.yaml。 |
| R2 材料 | 正文和附件取得并解析完整吗？ | 工程要求。附件失败、扫描件未解析、正文容器不明，保留待补采；不得以缺材料判“不相关”。 |
| R3 文种 | 是政策制度、规划目录、通用申报要求，还是具体事项结果？ | 沿用本分支口径：会议新闻、单个项目批复、采购公告、解读不作为政策正文；这属于实现口径，任务书没有逐项明确，应允许业务复核。 |
| R4 相关性 | 哪类投资项目适用？哪条措施改变方向、准入、要素或管理？ | 任务书四类含义的操作化。规则模式检查同一原文条款内的对象和措施，仅作初判，仍需复核；LLM按语义判断。 |
| R5 分类 | 条款实际发挥什么作用？ | 任务书明确四类；允许多标签是当前实现方案。每类单独提供可在原文定位的证据。 |
| R6 不确定性 | 是材料缺失、口径未定、模型失败，还是证据不成立？ | 分别补采、业务裁决、重跑或核对证据，不能把所有问题都交给人工从头读。 |

同一原文条款的对象词和措施词共现仍可能误判，例如新闻转述或否定句。因此 `rule-v3/scope-v3` 的正判只是候选建议，`need_review=true`；不能把规则覆盖率当成正确率。源文件是 `config/classification.yaml`，规则和LLM共用这份配置。

## 3. 四类判断表

以下是说明规则的自拟条款，不是某份真实政策的摘录。

| 类别 | 看实际作用 | 正例 | 易混边界 |
|---|---|---|---|
| 引导：往哪投 | 指定鼓励发展的产业、空间布局或建设方向 | 鼓励布局先进制造业重大项目 | “促进经济发展”之类泛泛表述不足以支持收录 |
| 准入：让不让投 | 规定项目能否建设及审批、核准、备案等前置门槛 | 固定资产投资项目应当开展节能审查 | 申请补助的资格不直接等于建设项目准入 |
| 保障：靠什么投 | 提供或倾斜配置土地、资金、信贷、能耗、人才 | 优先保障重大项目新增建设用地 | 有“资金”二字不等于保障；要有项目适用对象和措施 |
| 激励约束：投了怎样 | 奖补、税收、价格支持，或全过程监管、绩效、后评价、责任 | 对政府投资项目开展后评价 | 不能把本类收窄为财政补贴，也不能把所有行业监管都纳入 |

两组常用边界：节能审查→准入，能耗指标保障→保障；资金供给→保障，项目奖补或资金绩效监管→激励约束。有两种真实作用时可以并列，不能为了凑主类丢掉信息。

## 4. 尚不能由程序替业务方决定的边界

1. 综合改革文件中只有一条明确支持重大项目用地：建议保留文件并突出相关条款，但是否整篇正式收录待确认；当前LLM口径要求pending。
2. 钢铁超低排放差别化电价：必须核对直接适用对象和条款。仅能推测其促使企业技改，不能自动证明它属于投资项目政策。
3. 项目建设招投标监管：任务书包含项目全过程监管，不能整类排除；仍须确认该文件适用于工程建设项目，而非一般采购活动。
4. 征求意见稿：单独标记并复核，不能呈现为已生效正式政策。
5. 多标签：实现支持，但仍应让业务方确认使用习惯；每类必须有自己的证据。

这些边界及七个真实争议样本仍在 `BOUNDARIES-v0.6.md`。应记录业务确认人、时间、适用对象、原文证据及最终标签，再更新配置版本。模型自评分高不替代这个环节。

## 5. 已实现的规则修正

- 移除“两个宽泛关键词即可判yes”，改为正文条款中同时识别项目对象与实质措施；单纯出现“投资增长、项目推进”进入待判断。
- 补齐后评价、绩效评价、价格支持、产业方向及节能审查等候选词。
- 修正“中央预算内投资申报条件自动等于准入”的提示；去掉仅因标题含“实施细则”就判混杂的规则。
- LLM要求输出 `category_evidence`，逐类别核对连续原文；旧接口未提供映射或映射无效时，保留分类建议并强制复核，不静默通过。
- 合法的分类证据映射随判断理由入库，可回看；原有整篇证据字段继续保留。无需更换现有数据库结构。

## 6. 官网接入结构与现状

官方入口来自国家发改委官网的“地方发改委”导航：<https://www.ndrc.gov.cn/>。`config/provinces.json`记录31个省级地区的导航入口及证据URL，包含省、自治区、直辖市，不含副省级城市或兵团。入口记录不等于采集接通。

| 文件/模块 | 实际用途 |
|---|---|
| `config/provinces.json` | 31个地区官网入口清单，建立覆盖分母 |
| `scripts/discover_provinces.py` | 逐站探测首页和政策栏目候选，输出受阻和待适配情况；不自动启用猜测栏目 |
| `config/sources.yaml` | 已配置的具体栏目、域名/详情范围、列表机制和页数预算 |
| `collector.py` | 静态列表、政府网JSON、浙江unitbuild、江苏jpage、显式下一页与云南编码翻页 |
| `site_adapters.py` | 各站正文容器和元数据适配，新增云南正文定位 |
| `pipeline.py` | 列表队列、正文附件、去重入库、重试，以及采集停止原因 |
| `scripts/audit_sources.py` | 在独立临时数据库中验证发现→正文→附件→入库，输出JSON验收报告 |

配置现有国家3个栏目、8个省级地区8个栏目；另有禁用演示源。原有6个省级地区是浙江、江苏、重庆、福建、陕西、湖南；本次新增吉林、云南。其余地区仍需按台账逐站维护，不能宣称31省全部接通。

新增/修复能力：

- 江苏：从官方页面的`nextgroup`读取同源dataproxy下一组，处理桌面/移动重复列表；不硬编码unitid，不执行网页脚本。初次请求返回403，后续在线验证两组发现138条候选，证实分组接口可取得历史链接；抽样详情正文容器仍未定位，完整链路验收未通过。
- 云南：按官方页面现有编码解出下一页HTML，限制同源链接；正文只取`.show-content`。实测2页50条候选、2篇正文及其3个附件解析入库通过。仍非历史全量验收。
- 吉林：按官网吉林政策栏目接入TRS分页，实测2页27条候选、2篇正文及1个WPS附件解析入库通过。

## 7. 可复用运行方式

```bash
# 官网入口与栏目候选台账，不调用大模型
python scripts/discover_provinces.py

# 栏目接入验收：仅临时数据库；原件和临时库验收后清理
python scripts/audit_sources.py --source yn_policies,jl_policies --pages 2 --details 2

# 全部已启用来源抽样验收；存在失败时退出码1并写出原因
python scripts/audit_sources.py --pages 2 --details 1 --output docs/source-audit-latest.json

# 正式数据库持续采集（模型需按README配置）
python -m policy_collector.cli run --source yn_policies --prefer llm --limit 50
```

注意：审计脚本刻意使用规则模式，只验证工程链路；未测真实模型准确率。正式数据库中规则兜底文件仍进入待复核。正式定时命令以`python -m policy_collector.cli schedule --help`为准；现有调度器定期运行已启用来源，无需新增云提醒。

## 8. 后续验收标准

规则侧：由业务方确认的一批独立样本，分别统计收录精确率、漏收率、分类逐类效果、证据正确率、材料缺失率和人工复核率。不要只比较模型与AI初标的一致率，更不要强制二选一以降低复核率。

工程侧：以“地区—栏目”为单位记录最后成功时间、发现数、正文成功数、附件成功数、入库数、失败原因及分页终点；对照官网抽样核实漏链。历史回采和定期增量分别设置页数预算，达到预算不等于采全；新栏目通过列表、正文、附件及去重测试后再正式启用。

本轮自动化测试71项通过。31省目录和真实网络探测可以重复运行；当前没有完成31省每个政策栏目、全部历史文件的接入，也没有外部模型业务准确率验收结果。
